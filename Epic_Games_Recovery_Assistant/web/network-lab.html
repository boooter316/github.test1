DigitalOcean & Private Network Lab

Guides for a VPS you own, private VPN access, a restricted proxy, Kali Linux in VirtualBox, and PuTTY/SSH administration.

Cost and safety: This guide does not create cloud resources or spend money. You create and delete DigitalOcean resources yourself. A Droplet is billable while it exists, even when idle. Do not expose an unauthenticated proxy or remote admin service to the public internet.

1. Create your own DigitalOcean VPS

  1. Create/sign in to your DigitalOcean account and enable multi-factor authentication.
  2. Open DigitalOcean Droplets, choose a supported Ubuntu LTS image, region, and the smallest plan that meets your needs.
  3. Add an SSH public key during creation. Do not use password-only SSH for an internet-facing server.
  4. Choose a hostname, review the displayed monthly/hourly price and backups, then create the Droplet yourself. This project will not create a paid resource or store your cloud API token.
  5. Record the public IPv4 address shown in the Droplet control panel. Restrict inbound access with a DigitalOcean Cloud Firewall and the server firewall.
Keep SSH (TCP 22) limited to your current trusted public IP when possible. Open only the ports required for the service you intentionally run. Do not expose admin dashboards, databases, or proxy ports publicly.

Official docs: Droplets · Cloud Firewalls · SSH connection.

2. Build a private WireGuard VPN

Use this only for devices and traffic you own or are authorized to administer. Keep the WireGuard UDP port limited to the intended VPN service and use unique keys per device.

sudo apt update
sudo apt install wireguard ufw -y
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key
wg genkey | tee client_private.key | wg pubkey > client_public.key

Use the official WireGuard quick start to create /etc/wireguard/wg0.conf, assign a private tunnel subnet that does not overlap your home network, configure forwarding/NAT only if you intend to route client internet traffic, and add the matching peer public key. Never paste private keys into this website, GitHub, chat, or screenshots.

sudo systemctl enable --now wg-quick@wg0
sudo wg show
sudo ufw allow 51820/udp
sudo ufw status verbose

Before enabling UFW remotely, explicitly allow SSH from your trusted admin IP so you do not lock yourself out. Configure the DigitalOcean Cloud Firewall to match. Verify DNS, IPv4/IPv6 leak behavior, and that disconnecting the tunnel stops routed traffic if you require a kill switch.

Official guide: WireGuard Quick Start · DigitalOcean Firewall.

3. Run a restricted private HTTP proxy

A proxy forwards traffic for configured applications; it is not an encrypted VPN. Use a private address, authentication, and a firewall allowlist. Never run an open proxy.

sudo apt update
sudo apt install squid ufw -y
sudo systemctl enable --now squid
sudo systemctl status squid --no-pager

Configure Squid to listen only on the VPN interface/private address, permit only your VPN subnet or trusted client addresses, deny all other clients, and require authentication where appropriate. Validate the configuration before restarting:

sudo squid -k parse
sudo systemctl restart squid
sudo journalctl -u squid -n 50 --no-pager

Do not open TCP 3128 to the world. Allow it only from your VPN subnet in both UFW and the DigitalOcean Cloud Firewall. Avoid proxy rotation, public relay use, or forwarding traffic for unknown users.

Official docs: Squid documentation.

4. Kali Linux in Oracle VirtualBox

  1. Download VirtualBox from Oracle VirtualBox.
  2. Download the official prebuilt VirtualBox image from Kali Linux Virtual Machines; verify its published checksum.
  3. Import the appliance, set a strong VM password, and install updates from Kali's official repositories.
  4. Start with NAT networking for ordinary outbound updates. Use Host-only networking for isolated lab communication. Avoid Bridged mode unless you understand the exposure and have permission on that network.
  5. Take a clean snapshot before experiments. Use test systems you own or have written authorization to assess.

Do not expose the Kali VM's SSH, web services, or test tools to the public internet by default. The VM is a separate lab environment; it does not automatically become a DigitalOcean server.

Official docs: Kali VirtualBox guide · VirtualBox manual.

5. Connect with PuTTY using SSH

  1. Install PuTTY from the official PuTTY site.
  2. Use PuTTYgen to create an SSH key pair. Add the public key to the Droplet's authorized keys; keep the private key on your own device and protect it with a passphrase.
  3. In PuTTY, enter the Droplet's public IP and port 22, select SSH, and configure your private key under Connection → SSH → Auth/Credentials.
  4. Verify the server host-key fingerprint using a trusted channel before accepting it. Log in using the configured Linux account; use sudo only for tasks requiring administration.
  5. Disable password-based SSH only after key login has been tested in a second session and you have console recovery access.

PuTTY is an SSH terminal client for managing your own server. This guide does not configure C2, covert remote control, persistence, or command execution against third-party systems.

Official docs: PuTTY documentation · DigitalOcean SSH guide.

6. Check your VPS public IP and firewall

Find the public IPv4/IPv6 addresses in the DigitalOcean Droplet control panel. From an SSH session on your own server, these commands show the public egress address observed by the external service:

curl -4 https://icanhazip.com
curl -6 https://icanhazip.com
ip -brief address
sudo ufw status numbered
sudo ss -tulpn

The address returned by an external IP service is the server's current egress address; it can differ when traffic uses a VPN, NAT, or another gateway. Do not use IP geolocation as proof of a person's identity or account ownership.

Before going live: update the OS, use SSH keys and MFA, restrict inbound ports, enable unattended security updates where appropriate, monitor logs, back up configuration securely, and delete unused Droplets to stop ongoing charges.
