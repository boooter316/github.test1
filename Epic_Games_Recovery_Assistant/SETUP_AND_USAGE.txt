EPIC GAMES RECOVERY ASSISTANT — SETUP AND USAGE
================================================

CANONICAL PROJECT GUIDES
------------------------
The complete, maintained setup walkthrough is:
  ../docs/SETUP_GUIDE.md
The repository folder/component map is:
  ../docs/PROJECT_STRUCTURE.md

This file summarizes the Windows desktop app and its local tools. The
project is an independent organizer and defensive diagnostics toolkit; it
is not affiliated with Epic Games or other providers.

A. DOWNLOAD AND EXTRACT
-----------------------
1. Download the repository source ZIP or a current Windows build artifact.
2. Extract the ZIP to a normal folder, for example C:\Tools\Epic_Games_Recovery_Assistant.
3. Keep all folders and filenames intact. Do not run scripts from inside the
   ZIP preview.

B. WINDOWS DESKTOP APP — FIRST RUN
----------------------------------
1. Open the extracted Epic_Games_Recovery_Assistant folder.
2. Double-click OPEN_PROJECT.bat.
3. The setup checks for a C++17 compiler (g++) and may offer MSYS2/GCC setup.
4. The build also checks for Poppler pdftotext.exe for PDF text extraction.
5. Approve only the installations you expect. Reopen the terminal or restart
   Windows if a new PATH entry is not visible.
6. The build creates:
     Epic_Games_Recovery_Assistant.exe
     paf_evidence_scanner.exe
7. The native desktop dashboard launches after a successful build.

IMPORTANT: OPEN_PROJECT.bat does NOT install Node.js, start the browser
website, or open a browser. START_HERE.bat is an alternative desktop setup
path. run.bat launches the already-built native desktop app.

C. MAIN BROWSER MULTITOOL — SEPARATE APP
----------------------------------------
1. Install Node.js 26 LTS or newer from https://nodejs.org/.
2. Open PowerShell in the web folder:
     cd .\web
3. Start the server:
     node .\server.mjs
4. Open http://127.0.0.1:8080 in your browser.
5. Stop the server with Ctrl+C in PowerShell.

The browser multitool includes Dashboard, Recovery Assistant, Faze Jarvis AI,
Discord Security Scanner, Pro Multi-Platform Scanner, PDF Evidence Scanner,
Account Links, Account Connections, Wireshark & Ports, Account Status &
Details, Telegram Connect, Fortnite Skin Check, Setup & Install, and Script
Builder. Some optional integrations require separate server-side setup.
Do not put API keys or bot tokens in browser code or Git.

D. SEPARATE RECOVERY PANEL
--------------------------
The Recovery Panel lives in the repository's recovery-panel folder. It is
not the same application as the browser multitool.

Requires Node.js 26 LTS or newer. From recovery-panel:
     npm install
Set ADMIN_EMAIL, ADMIN_PASSWORD_SCRYPT (salt:hash), and SESSION_SECRET
(32+ random characters) in your local environment. Then run:
     npm start
Open http://localhost:3000.

See recovery-panel/README.md for password-hash generation and all settings.
Panel tabs are Recovery Records and PDF Evidence Scanner. Records are stored
in that browser's local storage; export a backup before clearing browser
data or changing devices.

The panel currently uses Express MemoryStore. Do not expose it publicly or
treat it as production-ready until a maintained persistent session store,
HTTPS, network restrictions, backups, and deployment controls are configured
and reviewed. A committed package-lock.json is not yet present; CI uses
npm install, not npm ci.

E. IP AND NETWORK TOOLS
-----------------------
The browser's Network Tools page and Windows helper provide local network
status and bounded private IPv4 TCP checks. Use these only on systems and
networks you own or are authorized to administer. Review web/README.md and
web/network-tools.html for the feature details.

The Windows helper does not capture credentials, change VPN connections,
upload reports, or send scanner files through a VPN/proxy. Do not use network
features to evade provider security or access systems without authorization.

F. PDF EVIDENCE SCANNERS
------------------------
The native C++ scanner uses Poppler pdftotext.exe to extract text. It does
not OCR image-only pages. Browser PDF scanning uses PDF.js loaded from a CDN
and requires internet access to load the library. Encrypted, damaged, or
image-only documents may not yield readable text.

Reports are evidence-organizing aids, not proof of account ownership or
credential validity. Keep source PDFs and exports private.

G. IP / ACCOUNT PRIVACY
-----------------------
Do not enter passwords, one-time codes, recovery codes, cookies, tokens,
full payment-card details, wallet seed phrases, or private keys. Never share
webhook URLs, API keys, or session secrets. Remove personal data and secrets
from logs before asking for support.

The app does not sign in to provider accounts, verify account ownership,
bypass account checks, or submit recovery requests automatically. Scanner
inputs and reports must remain local and must never be exfiltrated.

H. UPDATES AND TROUBLESHOOTING
------------------------------
The Windows updater requires GitHub CLI (gh) and authenticated access to the
private repository. It downloads a successful main-branch build artifact,
checks its SHA-256 manifest, backs up local files, and updates project files.
Close the app before updating. The updater does not execute downloaded code.

If a build fails, note the first meaningful error and compiler/runtime
versions. Remove passwords, tokens, cookies, IP addresses, and personal
information from logs before sharing. A green GitHub Actions run confirms
only the checks in that workflow; it does not guarantee every feature works
on every PC.

The Windows executable does not run on iPhone. Mobile users can access the
browser interfaces only when the web server is reachable over a trusted
network or a properly configured HTTPS deployment. Browser-local panel
records do not automatically sync between phone and PC.
